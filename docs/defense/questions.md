# Вопросы преподавателя и ответы

**Почему GitHub Pages?** Пользователь прямо заменил Vercel. Отклонение зафиксировано, сайт статический, автоматический деплой выполняет GitHub Actions. Условие оригинального ТЗ о Vercel нужно согласовать с преподавателем.

**Почему такое имя репозитория?** Учебный владелец lastuser55556 проверен; пользователь выбрал kursovaya_rabota. Это второе зафиксированное отклонение от имени tz-21-shinomontazh-koleso21 в PDF.

**Как рассчитывается R17 crossover?** База 2200, коэффициент 1.1, итого 2420. Хранение этой группы 3000 прибавляется отдельно, общий итог 5420. Надбавка автомобиля не применяется к хранению.

**Почему слот час, если работа 30–50 минут?** Такой шаг и четыре поста заданы ТЗ, остаток часа — резерв графика. Демонстрационная занятость из массива не заменяет реальную диспетчеризацию.

**Почему нельзя доверять клиентской валидации?** Браузерный JS можно обойти. Apps Script повторно проверяет телефон, email, списки, длины, слот и ID, сам задаёт created_at/new.

**Как защищены дубли при одновременной отправке?** Сервер берёт lock, проверяет request_id и записывает в критической секции. Проверка только на клиенте не защищает от двух запросов.

**Когда отправляется generate_lead?** Только после разбираемого ответа ok:true от приёмника. Нажатие кнопки и form_submit не доказывают создание строки.

**Почему fetch no-cors не подходит?** Ответ opaque невозможно прочитать. Тогда нельзя проверить ok:true и достоверно отправить generate_lead. Нужен реально читаемый ответ и проверка опубликованного Apps Script.

**Что дают UTM?** Source определяет источник, medium канал, campaign кампанию, content конкретное размещение, term дополнительную метку. Четыре обязательных метки заявки сохраняются в sessionStorage и передаются в Sheets. U-03 и U-12 имеют особые кампании по ТЗ.

**Почему возможна разница GA4 и Sheets?** Sheets считает серверные записи; GA4 зависит от разрешения аналитики, блокировщика, сети и scope. Конкретную причину подтверждают сверкой, а не угадывают.

**User acquisition и Traffic acquisition?** Первый источник нового пользователя против источника сеанса. Повторный пользователь может вернуться из другого канала.

**Открытая и закрытая воронки?** Открытая разрешает вход на промежуточном шаге. Закрытая требует первый шаг. На малой выборке числа могут совпасть.

**Зачем регистрировать Custom dimensions?** Передача параметра не гарантирует удобного использования в стандартных отчётах. Семь параметров регистрируются на уровне события.

**Почему три key events?** Так требует ТЗ: generate_lead, contact_click, messenger_click; они созданы. close_convert_lead и qualify_lead сняты. Встроенный purchase остался disabled, потому что интерфейс не разрешил снять отметку. Это честно зафиксированное отклонение от «других key events нет».

**Как избежать завышения DataLens?** Агрегировать каждый источник по date/source/campaign до соединения, использовать COUNTD ID. Соединение сырых строк может многократно умножить метрики.

**Можно ли суммировать Active users по датам?** Не без потери уникальности: один пользователь входит в несколько дней. Для общего KPI нужен корректный scope выгрузки.

**Где персональные данные?** Только в закрытой учебной Sheets при реальном подключении. В GA4 они не передаются. DataLens исключает name/phone/email, публичный репозиторий не хранит реальные leads.

**WINTER10 значит скидка 10%?** Нет утверждённых условий скидки в ТЗ. Интерфейс копирует код, калькулятор использует только заданные цены.

**Что осталось проверить?** Apps Script авторизован и опубликован, initializeProject успешна. Две учебные записи реально есть в Sheets, включая контрольную с Pages; повторный POST отклонён duplicate, статусы проверены.
