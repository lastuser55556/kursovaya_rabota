## Google Sheets, лист utm

Импортировать CSV. Создать отдельную ячейку config!B1 с реальным базовым URL, заканчивающимся `/`. Для строки 2 full_url (J2) использовать формулу:

```text
=config!$B$1&I2&"?utm_source="&ENCODEURL(D2)&"&utm_medium="&ENCODEURL(E2)&"&utm_campaign="&ENCODEURL(F2)&"&utm_content="&ENCODEURL(G2)&"&utm_term="&ENCODEURL(H2)
```

Протянуть вниз. При локали с `;` заменить разделители аргументов по правилам Sheets (формула выше использует функции с одним аргументом). Ссылки генерировать из реестра. U-04 ведёт прямо в календарь; U-09 в памятку по теме Shorts; U-10 на общий оффер, U-11 сразу к цене.

## Короткие ссылки

После подтверждения базового URL создать ссылки clck.ru или vk.cc для U-05, U-06, U-07, U-08. Записать выдачу сервиса в short_url. Не имитировать выдачу локальным редиректом. Открыть каждую из учебной публикации, снять адресную строку с пятью метками. Сверить source, medium, campaign, content, term после редиректа. Ни одной реально созданной короткой ссылки пока нет.

## Отработка всех 12 ссылок

1. После отдельного подтверждения публикации разместить подготовленный текст в учебном аккаунте проекта. Записать URL и дату.
2. Открыть саму публикацию инкогнито или на втором устройстве, нажать ссылку. Вставка URL в адресную строку не считается.
3. Сохранить реальный screens/utm/u-XX-url.png с метками и screens/utm/u-XX-realtime.png с соответствующим source.
4. Для U-01, U-05, U-07, U-09, U-10, U-11, U-12 создать заявку «Тест U-XX»; записать request_id и сверить 4 UTM в leads.
5. Через 24–48 часов снять traffic-acquisition.png с ≥6 реальными парами source/medium. При отсутствии данных писать PENDING, а не нули.

QR и афишу регенерировать после любого изменения конечного URL. Для U-12 сохраняется spring_tires_2027, как требует исходная строка реестра.
