# Диагностика пустого DebugView

## Текущий предел доказательств

Локальный `data-debug=true`, `script[data-ga4].dataset.status=loaded` и тест `K21.track` подтверждают настройки/вызов кода. Они не доказывают отправку `g/collect`, поступление событий в ресурс или отображение параметров в DebugView. Пустой DebugView нельзя отмечать PASS.

## Проверка по порядку

1. Сверьте Measurement ID веб-потока нужного ресурса с `G-YEMK5T27NW`. Номер ресурса и Measurement ID различаются. Проверьте, что DebugView открыт именно для ресурса 563008174.
2. Откройте опубликованный сайт с `?debug_mode=1`, проверьте загруженную версию analytics.js. Выполните настоящие действия: откройте страницу, нажмите расчёт калькулятора или кнопку записи. Вручную сочинённые collect-запросы не используются.
3. В Network браузера или Google Tag Assistant найдите запросы к `google-analytics.com/g/collect` или `analytics.google.com/g/collect`. Проверьте Measurement ID назначения, имя события и признак отладки. HTTP 200/204 доказывает успешную передачу запроса, но ещё не заменяет проверку DebugView. Сохраните реальный снимок запроса без персональных данных.
4. Если gtag.js загружен, а collect отсутствует или блокируется, проверьте ошибки JavaScript, браузерные privacy controls, расширения и сетевую блокировку сборщика. Загрузка библиотеки с googletagmanager.com не доказывает доступность отдельного домена google-analytics.com. Не отключайте защитные настройки без согласования. Сравнение в другом учебном браузерном сеансе помогает отделить код от окружения.
5. Если collect успешно уходит с правильным ID и debug, выберите тестовое устройство в DebugView, проверьте Realtime того же ресурса и действующие data filters. Проверьте, нет ли consent mode/клиентских ограничений, запрещающих Analytics cookies. В коде проекта consent mode не реализован; не приписывайте ему отказ без свидетельств.
6. Если все транспортные проверки успешны, но DebugView по-прежнему пуст, зафиксируйте BLOCKED с URL, временем, ID ресурса и реальными сетевыми доказательствами. Не объясняйте это только ожиданием стандартных отчётов.

По официальной документации Google DebugView обычно показывает события за секунды, Realtime за минуты. 24–48 часов относятся к обработке стандартных отчётов. Это разные этапы.

## Отключение отладки перед сдачей

Google указывает: для выключения отладки параметр `debug_mode` следует убрать из config; значение false не является надёжным выключением. Поэтому итоговая конфигурация должна добавлять `debug_mode: true` только для явно включённой тестовой сессии, а в обычной сессии не передавать параметр. Это отдельное исправление режима отладки, а не доказанная причина отсутствия событий.
